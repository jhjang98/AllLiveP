# ADR-0001: 플랫폼 아키텍처 — Next.js 단일 앱 + Supabase

- 상태: 승인 (2026-09-28, 설계 검토 시 이견 없음)
- 결정자: 사용자 / 작성: Claude

## 결정

1. **Next.js(App Router) 단일 앱**을 Vercel에 배포한다. 공개/기관회원/관리자는 라우트 그룹으로 분리하고 별도 서비스로 나누지 않는다.
2. **Supabase**를 Postgres+Auth+Storage로 사용한다. 읽기는 RLS 기반 클라이언트 접근, 업무규칙이 있는 쓰기와 개인정보 접근은 전부 Next.js Route Handler(service-role) 경유.
3. **조건부 인프라 금지 원칙**: Redis·큐·검색엔진·서비스 분리는 도입하지 않는다.

## 근거

- 레거시 3개 사이트가 DB를 공유하며 사실상 하나의 도메인 — 분리 비용만 있고 이득이 없다
- 공고 수백~수천 건, 동시 사용자 소규모 → Postgres 단일로 충분
- 개인정보 열람 로그·열람기한 검증은 우회 불가능한 단일 경로(서버 API)가 필요 — RLS만으로는 "열람 기록"을 강제할 수 없다

## 전환 조건 (이 수치를 넘으면 재검토)

- 검색: 공고 1만 건 초과 또는 검색 p95 500ms 초과 시 → Postgres FTS/외부 검색 검토
- 큐: 이메일 발송 실패율 1% 초과 또는 분당 100건 초과 시 → 큐 도입 검토
- 분리: 관리자 트래픽이 공개 사이트 성능에 영향을 줄 때 → 배포 분리 검토

## 결과

- 저장소 1개, 배포 파이프라인 1개. 환경: local / staging / production (Supabase 프로젝트 2개: stg·prod)
