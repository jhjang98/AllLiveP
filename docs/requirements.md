# AllLiveP 요구사항 (초안 v0.1)

> 상태: **초안 — 사용자 확정 전**
> 작성일: 2026-09-28
> 근거: 사용자 구두 요구사항 + 기존 사이트(https://alllivec.co.kr/) 외부 관찰
> 기존 소스(PHP)·DB 분석은 아직 수행하지 않음. 분석 후 본 문서를 개정한다.

## 1. 프로젝트 개요

- 기존 임상시험 대상자 모집 공고 사이트(AllLiveC)를 **플랫폼 형태(AllLiveP)로 리뉴얼**한다.
- 핵심 변경점: 기존에는 운영자가 공고를 등록했으나, 리뉴얼 후에는 **기관회원이 직접 가입 → 관리자 승인 → 모집공고 직접 등록**하는 구조로 전환한다.
- 구성: (a) 모집공고 사이트(일반 사용자용), (b) 관리자 페이지(플랫폼 운영자용), (c) 기관회원용 공고 관리 기능.
- 기술 환경: **Supabase**(DB/인증/스토리지) + **Vercel**(호스팅) 기반 신규 프로젝트.
- 기존 소스(PHP, CodeIgniter 계열)와 DB를 분석 자료로 활용하되, 코드는 신규 작성한다.

## 2. 이해관계자 (행위자)

| 행위자 | 설명 |
|---|---|
| 일반회원 | 임상시험 참여 희망자. 공고를 탐색하고 지원한다 |
| 비회원 | 공고 열람 및 (기존 사이트 기준) 간편 신청이 가능한 방문자 |
| 기관회원 | 모집공고를 등록·관리하는 주체. **병원/임상시험센터로 확정** (2026-09-28) |
| 플랫폼 관리자 | 기관회원 승인, 공고 검수, 회원·콘텐츠 관리 담당 운영자 |

## 3. 요구사항 (EARS)

### 3.1 공고 탐색 (일반 사용자)

- REQ-001 (항상) 시스템은 항상 모집 중인 공고 목록을 질환 카테고리별로 제공한다.
- REQ-002 (항상) 시스템은 항상 공고 검색·필터(질환, 지역, 성별, 나이 등 — 항목 확정 필요)를 제공한다.
- REQ-003 (항상) 공고 상세는 질환, 시행기관/병원, 모집조건(성별·나이), 모집 상태, 의뢰기관을 표시한다. (표시 항목은 기존 DB 분석 후 확정)
- REQ-004 (조건일 때) 공고가 모집 마감 상태일 때, 시스템은 해당 공고에 지원 접수를 받지 않는다.

### 3.2 지원 (일반회원)

- REQ-010 (이벤트) 사용자가 공고에 지원하면, 시스템은 지원 내역을 저장하고 해당 공고의 기관회원이 열람할 수 있게 한다.
- REQ-011 (항상) 일반회원은 마이페이지에서 자신의 지원 내역을 조회할 수 있다.
- REQ-012 (예외 상황에서) 이미 지원한 공고에 다시 지원하면, 시스템은 중복 지원을 차단하고 안내한다.
- REQ-013 (항상) 공고 지원은 **회원 전용**이다. 비회원 간편 신청은 제공하지 않는다. (확정 2026-09-28, 기존 사이트 방식에서 변경)

### 3.3 기관회원 가입·승인 (신규 핵심 기능)

- REQ-020 (이벤트) 기관이 회원가입을 신청하면, 시스템은 계정을 "승인 대기" 상태로 생성한다.
- REQ-021 (조건일 때) 기관회원이 승인 대기 상태일 때, 시스템은 공고 등록 기능을 제공하지 않는다.
- REQ-022 (이벤트) 관리자가 기관회원을 승인하면, 시스템은 해당 계정에 공고 등록 권한을 부여하고 승인 사실을 통지한다.
- REQ-023 (이벤트) 관리자가 가입 신청을 반려하면, 시스템은 반려 사유와 함께 통지한다.
- REQ-024 (이벤트) 기관이 가입을 신청하면, 시스템은 **사업자등록증** 제출을 요구하고, 관리자가 서류를 확인해 수동으로 승인·반려한다. (확정 2026-09-28; 추가 증빙은 운영하며 확대)

### 3.4 공고 등록·관리 (기관회원)

- REQ-030 (조건일 때) 기관회원이 승인 상태일 때, 공고를 등록·수정·마감할 수 있다.
- REQ-031 (이벤트) 기관회원이 공고를 등록하면, 시스템은 공고를 "검수 대기" 상태로 저장하고 **관리자 검수(승인) 후 게시**한다. (확정 2026-09-28)
- REQ-031a (이벤트) 관리자가 공고를 반려하면, 시스템은 반려 사유와 함께 기관회원에게 통지한다.
- REQ-032 (항상) 기관회원은 자기 기관의 공고와 그 지원자 목록만 열람할 수 있다.
- REQ-033 (예외 상황에서) 승인 취소(정지)된 기관회원이 접근하면, 시스템은 공고 관리 기능을 차단한다.

### 3.5 관리자 페이지

- REQ-040 (항상) 관리자는 기관회원 가입 신청 목록과 승인/반려 처리를 수행할 수 있다.
- REQ-041 (항상) 관리자는 전체 공고·회원·지원 내역을 조회·관리할 수 있다.
- REQ-042 [확정 필요] 기존 관리자 페이지 기능 중 이관할 범위 (기존 소스 분석 후 목록화)

### 3.6 데이터 이관

- REQ-050 **데이터 이관은 하지 않는다.** 신규 플랫폼은 빈 DB로 시작한다. (확정 2026-09-28)
- REQ-051 기존 DB는 스키마·코드표(상태, 적응증 등) 참조 용도로만 접근한다. 실데이터 접근 정보(IP·계정)는 사용자가 제공 예정.

### 3.7 기관회원 페이지 (기존 CRM 흡수)

- REQ-060 (항상) 기관회원 페이지는 기존 CRM(alllivecrm.co.kr)의 대상자 열람 기능을 흡수한다. 별도 CRM 사이트는 만들지 않는다. (확정 2026-09-28)
- REQ-061 (이벤트) 기관회원이 지원자 개인정보를 열람하면, 시스템은 열람자·일시·IP를 기록한다. (기존 컴플라이언스 규칙 승계)
- REQ-062 (조건일 때) 공고의 열람기한(모집종료 + 열람가능기간)이 지났을 때, 시스템은 지원자 정보 열람을 차단한다.

## 4. 비기능 요구사항 (초안)

- NFR-001 Supabase Auth 기반 인증, Row Level Security로 기관별 데이터 격리
- NFR-002 개인정보(연락처·건강정보)는 저장·로그에서 마스킹 원칙 적용
- NFR-003 **모바일 웹(반응형)으로 대응한다. 네이티브 앱은 만들지 않는다.** (확정 2026-09-28)

## 4a. 과금 정책

- **공고 등록은 무료로 유지한다.** 유료화는 시스템 밖의 별도 계약 절차로 진행한다 — 결제 기능은 이번 범위에서 제외. (확정 2026-09-28)

### 3.8 알림·예비참여희망자 (확정 반영)

- REQ-070 (이벤트) 지원 접수·상태 변경·기관 승인/반려·공고 검수 결과가 발생하면, 시스템은 **이메일로** 해당 당사자에게 통지한다.
- REQ-071 (항상) 시스템은 예비참여희망자 등록(관심질환·연락처를 등록해두면 맞는 공고를 안내받는 기능)을 제공한다. 기존과 같이 휴대폰 SMS 인증 기반으로 등록·조회한다.

## 7. 용어집 (초안)

| 용어 | 정의 |
|---|---|
| 공고 | 임상시험 대상자 모집 공고 게시물 |
| 지원 | 일반회원(또는 비회원)이 특정 공고에 참여 의사를 접수하는 행위 |

| 승인 | 관리자가 기관회원의 가입을 허가하여 공고 등록 권한을 부여하는 행위 |
| 검수 | 게시 전 관리자가 공고 내용을 확인하는 절차 (도입 여부 확정 필요) |
