# 도메인: 기관회원 (institution)

> 상태: 초안 v0.1 (2026-09-28) — 사용자 확인 전
> 신규 핵심 도메인. 레거시의 agency(기관 마스터) + admin(type 2 실시기관 계정) + CRM 열람 기능을 흡수·재설계.
> 기관회원 유형은 병원/임상시험센터로 확정 (2026-09-28).

## 용어

| 용어 | 정의 |
|---|---|
| 기관 | 병원/임상시험센터 법인 단위. 공고의 주체 |
| 기관 담당자 | 기관에 소속되어 플랫폼을 사용하는 개인 계정 |
| 승인 | 관리자가 기관의 가입을 허가하여 공고 등록 권한을 부여하는 것 |

## 구조

- **기관(organization) 1 : N 담당자(member)** 구조를 제안. 첫 가입 신청자가 기관 대표 담당자가 되고, 승인 후 담당자를 추가 초대할 수 있다. [확정 필요: 초기 버전에서 기관=계정 1개로 단순화할지]
- 기관 정보: 기관명, 사업자등록번호, 주소(+좌표), 대표 연락처, 로고, 소개
- 담당자 정보: 이름, 이메일(로그인), 연락처, 직책

## 상태

| 상태 | 설명 |
|---|---|
| pending | 가입 신청, 승인 대기 |
| approved | 승인 — 공고 등록·지원자 열람 가능 |
| rejected | 반려 (사유 통지, 재신청 가능) |
| suspended | 정지 (관리자 조치) — 로그인은 되나 기능 차단 |

## 상태전이

```
가입신청 ──▶ pending ──관리자 승인──▶ approved ◀──해제── suspended
                │                        │
                └─관리자 반려─▶ rejected   └──관리자 정지──▶ suspended
                        │
                        └──재신청──▶ pending
```

## 계산·판정 규칙

- R-I01 공고 등록 가능 = 기관 상태 approved
- R-I02 지원자 열람 가능 = approved AND 자기 기관 공고 AND 열람기한 내

## 권한

| 행위 | pending | approved | suspended | 관리자 |
|---|---|---|---|---|
| 로그인·기관정보 조회 | O | O | O | O |
| 기관정보 수정 | O | O | X | O |
| 공고 등록·관리 | X | O | X | O |
| 지원자 열람·상태변경 | X | O | X | O |
| 담당자 초대 | X | O | X | O |

## 제약·정책

- 가입 시 증빙 제출: **[확정 필요]** — 항목(사업자등록증, 병원 인허가 등)과 승인 기준은 사람이 정한다
- 개인정보 열람 시 열람자·일시·IP 기록 (레거시 컴플라이언스 승계)
- 레거시의 의뢰사(sponsor, type 1) 열람 기능은 1차 범위에서 제외하고, 공고의 의뢰기관은 표기 정보로만 다룬다 [확정 필요]
- 레거시 CRM의 링크 기반 로그인(암호화 파라미터)은 승계하지 않는다. Supabase Auth 표준 로그인 사용

## 오류 케이스

- E-I01 pending/suspended 상태에서 공고 등록 시도 → 차단, 상태 안내
- E-I02 동일 사업자등록번호 중복 가입 신청 → 차단, 기존 기관 담당자 초대 안내
- E-I03 rejected 후 동일 내용 재신청 → 허용하되 반려 이력 관리자에게 표시

## 확정 및 기본값

1. 가입 증빙: **사업자등록증 제출 + 관리자 수동 승인** (사용자 확정 2026-09-28)
2. 기관 구조: 데이터 모델은 기관 1 : N 담당자로 설계하되, **1차 화면은 기관당 담당자 1계정**으로 시작 (기본값 채택 — 이견 시 변경)
3. 의뢰사(스폰서) 계정: **1차 범위 제외**, 공고의 의뢰기관은 표기 정보로만 (기본값 채택)
