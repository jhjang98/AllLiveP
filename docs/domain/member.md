# 도메인: 일반회원 (member)

> 상태: 초안 v0.1 (2026-09-28) — 사용자 확인 전
> 레거시 대응: `account` + account_disease/scrap. 데이터 이관 없음 — 전원 신규 가입.

## 용어

| 용어 | 정의 |
|---|---|
| 일반회원 | 임상시험 참여를 희망해 가입한 개인 |
| 매칭정보 | 관심질환, 건강인/질환자 여부, 거주지역 — 맞춤 공고 추천에 사용 |
| 본인확인 | 지원 전 실명·연락처·성별·생년월일을 확정하는 절차 |
| 스크랩 | 관심 공고 저장 |

## 상태

| 상태 | 설명 |
|---|---|
| active | 정상 |
| unverified | 가입했으나 본인확인 전 (열람·스크랩 가능, 지원 불가) |
| withdrawn | 탈퇴 (개인정보 파기, 법정 보존 항목만 분리 보관) |

- 레거시의 휴면(1년 미접속 분리보관) 정책: 현행 개인정보보호법상 유효기간제 의무는 폐지되었으므로 도입 여부 [확정 필요]

## 상태전이

```
가입 ──▶ unverified ──본인확인──▶ active ──탈퇴──▶ withdrawn
```

## 계산·판정 규칙

- R-M01 지원 가능 = active (본인확인 완료)
- R-M02 나이 판정: 생년월일 기준 만 나이로 공고 모집조건과 비교
- R-M03 맞춤 추천: 관심질환·성별·건강인 여부가 공고 조건과 일치하는 모집중 공고

## 권한

- 자기 정보·지원 내역·스크랩만 접근 (RLS: user_id = auth.uid())
- 마케팅 수신 동의는 별도 플래그 + 변경 일시 기록 (법정 요구)

## 제약·정책

- 인증: Supabase Auth. 이메일+비밀번호, SNS 로그인(카카오/네이버/구글/애플 — 제공 범위 [확정 필요], Supabase 기본 제공은 구글/애플/카카오, 네이버는 커스텀 필요)
- 본인확인 수단: NICE 본인인증 유지 여부 [확정 필요]. 대안: 휴대폰 SMS 인증(실명 확정력은 낮음)
- 필수 수집: 이름, 연락처, 성별, 생년월일, 이메일 / 선택: 매칭정보, 마케팅 동의
- 탈퇴 시 지원 이력 처리: 개인정보는 비식별화하되 기관이 이미 열람한 지원 건의 처리 규칙 [확정 필요]

## 오류 케이스

- E-M01 미확인(unverified) 상태로 지원 시도 → 본인확인 유도
- E-M02 동일 실명+연락처로 이미 확인된 계정 존재 → 중복 가입 차단, 기존 계정 안내 (레거시 정책 승계)
- E-M03 탈퇴 회원의 재가입 → 허용 (단 기존 이력과 연결하지 않음)

## 확정 및 기본값

1. 본인확인: **휴대폰 SMS 인증**으로 시작 (사용자 확정 2026-09-28; NICE 본인인증은 추후 검토)
2. 예비참여희망자 풀: **유지** (사용자 확정 2026-09-28). 기존처럼 SMS 인증 기반 등록·조회, 회원가입 없이 가능 — "지원"이 아니라 관심 등록이므로 회원 전용 정책과 충돌하지 않음
3. SNS 로그인: **카카오 + 구글**로 시작 (기본값 채택 — 네이버·애플은 추후; 이견 시 변경)
4. 휴면 정책: 도입하지 않음 (기본값 채택 — 법정 의무 아님)
5. 탈퇴 시 지원 이력: 개인정보 비식별화 후 통계용 보존 (기본값 채택)
