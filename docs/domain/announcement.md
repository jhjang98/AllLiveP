# 도메인: 공고 (announcement)

> 상태: 초안 v0.1 (2026-09-28) — 사용자 확인 전
> 레거시 대응: `project` 테이블. 신규는 "기관회원이 직접 등록 → 관리자 검수 → 게시" 구조로 재설계.

## 용어

| 용어 | 정의 |
|---|---|
| 공고 | 임상시험 대상자 모집 공고. 기관회원이 작성하고 관리자 검수 후 게시된다 |
| 검수 | 관리자가 게시 전 공고 내용을 확인하여 승인/반려하는 절차 |
| 적응증 | 시험 대상 질환 분류 코드 (공고당 1~3개) |
| 대상구분 | 질환자 / 건강인 / 모두 |
| 조기마감 | 모집 종료일 전에 기관회원 또는 관리자가 모집을 종료하는 것 |
| 열람기한 | 모집 종료 후 지원자 개인정보를 열람할 수 있는 기간 (개월) |

## 상태

| 상태 | 설명 | 레거시 대응 |
|---|---|---|
| draft | 작성중 (기관회원만 열람) | T 가등록 |
| pending_review | 검수 대기 (제출됨) | W 대기 |
| rejected | 반려 (사유 포함, 수정 후 재제출 가능) | R 반려 |
| approved | 승인됨 — 모집기간에 따라 노출이 결정됨 | Y |
| closed | 마감 (기간 종료 또는 조기마감) | N |

- 공개 사이트 노출 = `approved` 이면서 모집기간 내 (시작 전이면 "모집예정" 표기 여부는 화면설계에서 결정)
- 별도 숨김 플래그(관리자 강제 비노출)를 둔다 (레거시 show_status_yn 대응)

## 상태전이

```
draft ──제출──▶ pending_review ──관리자 승인──▶ approved ──기간종료/조기마감──▶ closed
                    │                              ▲
                    └──관리자 반려──▶ rejected ──수정 후 재제출──┘ (pending_review로)
```

- 전이 주체: 제출/재제출·조기마감 = 기관회원, 승인/반려 = 관리자, 기간마감 = 시스템(스케줄러)
- approved 이후 내용 수정 시 재검수 필요 여부: **[확정 필요]** (제안: 모집조건·본문 변경은 재검수, 오탈자 수준은 즉시 반영)

## 계산·판정 규칙

- R-A01 모집중 판정: `status = approved AND started_at <= today <= end_at AND early_closed = false`
- R-A02 마감 전환: `end_at < today` 이면 시스템이 closed로 전환 (일 배치 또는 조회 시 판정)
- R-A03 열람기한: `end_at + reading_period(개월)`. 경과 시 지원자 개인정보 열람 차단 (지원 도메인 참조)
- R-A04 지원 가능 판정: 모집중 + 지원자의 성별·나이가 모집조건에 부합 + 중복 지원 아님

## 권한 (초안 — 확정은 사람이 한다)

| 행위 | 일반회원 | 기관회원(승인) | 관리자 |
|---|---|---|---|
| 게시된 공고 열람 | O | O | O |
| 공고 작성·수정·제출 | - | 자기 기관 것만 | O |
| 검수 승인/반려 | - | - | O |
| 조기마감 | - | 자기 기관 것만 | O |
| 강제 비노출 | - | - | O |

## 제약·정책

- 필드 구성은 레거시를 계승하되 간소화: 제목/노출제목, 프로토콜번호, 적응증 1~3, 임상단계, 대상구분, 성별, 나이 범위, 목표인원, 모집기간, 참여기간 텍스트, 본문(리치텍스트), 썸네일, 첨부(모집공고문), 실시 지역·장소
- 신규에서는 기관회원 = 실시기관이므로 공고-기관 연결은 단일 기관 기본. 의뢰기관 표기는 텍스트 필드로 시작 **[확정 필요]**
- 레거시의 신청방식 5종(source_callcenter)은 콜센터 운영 전제 — 신규는 "플랫폼 내 지원" 단일 방식으로 시작 **[확정 필요]**
- 사례비: 레거시는 본문에 포함. 신규에서 별도 필드로 둘지 **[확정 필요]** (검색·비교 기능에 유리)

## 오류 케이스

- E-A01 마감된 공고에 지원 시도 → 거부, "모집이 마감되었습니다"
- E-A02 미승인 기관회원의 공고 작성 시도 → 거부
- E-A03 pending_review 상태의 공고 수정 → 허용 여부 [확정 필요] (제안: 수정하면 검수 대기 유지, 검수자에게 최신본 표시)
- E-A04 타 기관 공고 수정 시도 → 거부 (RLS)

## 확정 및 기본값 (기본값은 이견 시 변경)

1. approved 후 수정: 모집조건·본문 변경은 재검수(pending_review로 복귀, 기존 게시본은 유지 노출), 그 외 경미한 수정은 즉시 반영 (기본값 채택)
2. 의뢰기관 정보: 텍스트 필드로 시작 (기본값 채택)
3. 사례비: 별도 필드 없이 본문에 기재 (기본값 채택 — 레거시 동일; 검색 니즈가 생기면 필드 추가)
4. 모집예정 공고: 시작일 전에는 비노출, 모집중만 노출 (기본값 채택)
